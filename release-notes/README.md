# 面向用户的变更片段

每个产品变更随 PR 新增一个唯一命名的 JSON 文件，使用简洁中文描述用户能感知的变化。
部署入口自动汇总上次上线到本次 HEAD 之间**新增**的 JSON 文件。已发布片段不改写或复用文件名，纠错请新增片段。
纯测试、内部重构、CI 调整通常无需用户公告；管理员仍需审核本次草稿是否完整、准确。

```json
[
  { "kind": "new", "text": "说明新增能力及适用场景。" },
  { "kind": "improved", "text": "说明原有操作的体验改善。" },
  { "kind": "fixed", "text": "说明用户遇到的问题及修复结果。" }
]
```

允许 `new / improved / fixed`；每条不超过 500 字，合并后最多 50 条。禁止凭证、内部路径、未上线承诺或复制完整技术提交日志。
没有片段时会生成待补充草稿，不会自动编造功能说明。片段及 Git 差异不能代替人工审核，也不会自动发布给用户。
具体部署入口与失败重试见 `deploy/RELEASE_NOTES.md`。
