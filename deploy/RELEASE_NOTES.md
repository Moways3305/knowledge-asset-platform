# 版本日志

系统管理员在“运行与接入 → 版本日志管理”创建草稿，按新增、优化、修复填写内容。
先保存或预览，再点击“确认发布”。所有在职登录用户均可从侧栏底部“更新日志”查看。

- 草稿仅当前工作身份为系统管理员的用户可读写，其他公司角色不可访问管理接口。
- 发布后内容不可修改，保留发布人、发布时间和审计记录；修正说明请另发新版本日志。
- “发布后提醒用户”控制更新日志入口的未读提示，不发送邮件或企业微信消息。
- 已读按账号持久化，仅确认当前打开页面中的日志；静默发布不会增加未读数。
- 相同版本号不能重复创建；多人编辑草稿时，过期修改会被拒绝，请关闭编辑器后重新打开最新草稿。
- 首次部署为空列表，不自动生成或发布历史说明、演示内容。

## 部署

本功能新增迁移 `0074_release_notes`，创建日志和已读记录两张表。
按现有生产流程备份数据库，构建 `migrate`、`backend`、`frontend`，先执行迁移，再更新服务。
发布日志不改变代码、容器、数据库结构或实际服务版本。

根目录部署环境文件中的 `APP_VERSION` 表示本次实际部署的服务版本，默认保留原值 `0.1.0`。
Compose 将其传给后端；更新日志页、运维接口及 FastAPI 元信息共用此值。
版本日志中的版本号是管理员编写的发布说明，两者独立，管理员应在功能实际部署后发布对应说明。

迁移回滚会删除日志及已读记录；如需回滚，应先备份这两张表。
