# 项目审批目录恢复

项目审批创建版本时保存确认目录、目录规则版本和确认人。审批异常会释放已提交的
`approving` 状态，转为 `approval_failed`，来源任务恢复为 `waiting_review`，并记录失败审计。
已取消的任务保持取消状态。此修复不自动改写部署前已经卡住的审批任务。

## 历史目录

部署后，由业务治理角色使用现有历史目录迁移入口：

1. `GET /api/v1/admin/directory-migration` 刷新候选；此步骤仅生成治理候选，尚不修改资产目录。
2. 核对候选项目和目录。`candidate_source=approval_snapshot` 表示来自原审批确认快照。
3. 使用现有确认操作 `POST /api/v1/admin/directory-migration/confirm` 提交候选 ID。
   确认只更新目录治理字段并记录审计，不重新上传、审核或索引。

快照候选仅适用于：已通过的项目入库审批、审批与入库任务指向同一资产、结果版本为
当前版本、快照项目与资产项目一致、目录仍启用且属于该范围。支持顶层 `directory_key`
和 `naming.directory_key`，两者冲突时不采用快照。已有目录不会通过快照覆盖，候选生成后
另行确认的目录也不会覆盖。没有可信候选的记录保留待治理状态，人工确认后处理。

生产回填需先核对候选；本地测试不会执行生产回填。
