# 知识维护、复核与纠错闭环

## 使用入口

导航「知识维护」汇总当前身份有权管理的待安排、待复核、待纠错资料，以及本人提出后等待验证的纠错。资料详情中的「知识维护与复核」提供操作。

个人资料由本人管理，项目资料由所属项目经理管理，公司资料由具有公司治理权限的业务身份管理。系统管理员没有业务资料权限。指定维护人不会扩大其原有权限；候选维护人必须具有该库的管理权限。

## 流程

1. 指定维护人并安排未来的复核日期，填写操作原因。
2. 到期进入维护待办并发送去重通知，不自动归档或认定资料失效。每日扫描与现有生命周期任务一起运行。
3. 复核通过需要指定下一次复核日期；发现问题可标记需要更新。资料或目录等修改后，原复核不再代表当前版本已验证。仅调整维护人或复核日期保留原有有效复核，但不改变最近复核时间或复核人；已经待复核的内容不会因此恢复为已复核。所有安排变更仍刷新并发令牌，旧页面提交会被拒绝。
4. 修正资料元信息使用现有「编辑资料」。原文件正文变化仍通过正式上传流程入库，然后关联新版；此功能不直接改写原文件。
5. 新版必须已复核、具有有效当前版本，与旧版属于同一库且保密等级一致。显式确认后，在同一事务关联新版并归档旧版，沿用现有生命周期审计和检索隔离。禁止替代链和循环。撤销替代关系不会自动启用旧版，启用需再次人工确认。
6. 可发现资料的业务用户可提出纠错；同一用户对同一资料最多一项未完成纠错。只有管理人和提出者可以查看对应纠错；普通用户不获得他人的纠错内容。处理说明对提出者仅返回安全提示，不能借此绕过摘要/原文权限。
7. 实际修改资料或关联新版后，管理人将纠错标记为待验证；仅修改维护人或复核日期不算内容修正。仍有开放纠错时不能确认复核通过。
8. 处理完成后复核当前资料，再由纠错提出者验证是否解决；未解决可重新打开。验证时校验当前内容指纹及新版关联，资料再次改动会要求重新核查。个人提出的纠错不是新增原文访问授权。

## 接口

- `GET /api/v1/knowledge-maintenance`：有权限的维护待办，先过滤再分页/计数。
- `GET /api/v1/knowledge/{asset_id}/trust`：复核状态及调用人可见纠错。
- `PATCH /api/v1/knowledge/{asset_id}/trust/policy`：维护人、复核时间。
- `POST /api/v1/knowledge/{asset_id}/trust/review`：复核通过或需要更新。
- `POST /api/v1/knowledge/{asset_id}/trust/replacement`：关联新版并归档；传入空新版可撤销关联。
- `GET /api/v1/knowledge/{asset_id}/trust/replacements`：按标题查找同库、同等级的已复核新版候选；操作时仍再次校验。
- `POST /api/v1/knowledge/{asset_id}/trust/corrections`：提出纠错。
- `POST /api/v1/knowledge/{asset_id}/trust/corrections/{correction_id}`：处理、验证、重新打开。

资产写操作使用资产的 `expected_updated_at`；纠错状态转换使用纠错记录的 `expected_updated_at`。冲突返回 409，不自动重放写请求。通知由同事务 Outbox 事件驱动，正文及纠错内容不进入事件负载，读取和外部投递时重新校验权限。

## 部署与范围

需要数据库迁移 `0076_knowledge_review_loop`，上线前备份并沿用发布脚本、镜像检查和健康验证。旧资产不回填虚假的复核结果、不自动分配维护人、不批量归档；在维护待办中逐步安排即可。

本次提供页面和 HTTP API，尚未新增远程 MCP 工具。部署到服务器后还需使用实际身份验收通知、权限、新版原文与默认检索隔离。迁移降级会删除新增纠错记录，生产回滚应保留数据库迁移并先评估数据保留。
