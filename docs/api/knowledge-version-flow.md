# 资料更新与版本历史接口

资料详情的「更新这份资料」创建与原资料、原版本绑定的上传任务。文件继续通过原有解析、确认、命名及索引流程；任务详情提供原库、项目、资料区、目录、密级和新版本号，页面默认沿用，服务端再次校验。

管理权限沿用集中策略：个人库本人、项目库该项目经理、公司库治理角色。维护人分配、读取权限和系统管理员身份不自动赋予更新权限。更新开始时检查资产更新时间；原资料已经替代、归档、当前版本变化或进入个人资料项目使用锁时，拒绝更新或确认。新版本号必须高于原版本。

上传和入库不自动替代旧版。回原资料的「版本历史与差异」跟踪任务，打开新版完成内容复核，再明确确认「替代并归档旧版」。替代沿用已有复核、未处理纠错、同库同密级及双资产版本时间校验。旧文件不覆盖、不删除；旧版退出默认检索与问答，历史入口及替代指针保留。可连续更新 V1、V2、V3，旧版指向当前终端版本，禁止自关联和循环。

历史 API 仅沿有权限的节点遍历，隐藏节点和已删除资料不返回；记录较多时返回截断提示。差异 API 只比较关联且可见的两个版本，展示版本、正式目录和安全摘要。L3/L4 及跨项目摘要不回退到原始正文摘要。本功能不宣称提供原文件全文差异或旧版原文下载，也不扩大原文授权。

新增接口：

- `POST /api/v1/ingest/upload`：沿用既有上传通道及代理限制；更新时额外提供 `update_of_asset_id`、`version_label`、`expected_updated_at`，普通上传不需要这些字段。
- `GET /api/v1/knowledge/{asset_id}/versions`：版本、更新任务、当前指向和操作能力。
- `GET /api/v1/knowledge/{asset_id}/versions/compare?left=...&right=...`：安全摘要与版本元信息比较。

数据库迁移 0077 增加入库任务来源关联及新版本标签。已有数据保持空值，不根据文件名猜测历史关系；没有来源记录时不能假造上传来源。已有新版关系仍可在原治理入口维护。回滚若已有更新来源记录会拒绝移除字段，避免丢失可追溯关系。
