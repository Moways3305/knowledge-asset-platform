# 检索与原文预览复测

## 检索

标题和标签的字面匹配与 WeKnora 文本片段召回合并。两路都执行现有权限裁剪；
标题准确命中、前缀及包含命中优先于仅标签命中；原查询和扩展词都参与此排序，
不能让标签相同的短标题案例挤占真正的主题文件。扩展词仍由模型推理，不保证每个口语题都命中。
元信息命中不能被当作原文证据。归档、非当前版本、索引失败与待确认资料仍不可参与检索。
标题/标签匹配各次最多返回 100 个可发现候选；按固定顺序每批扫描 100 条，
不可见资料不占用候选名额。每次最多扫描 2000 行（20 批），达到预算后停止扫描，
保留已放行的元信息匹配和正常片段召回结果，并记录安全事件
`retrieval_metadata_scan_budget_exhausted`。此时返回的是有限候选，空结果不证明没有更多可见匹配；
可通过更具体的标题、标签或目录缩小范围。不会继续无上限扫描，也不会放宽权限。
空白查询不进入底层召回或元信息匹配；统一检索 API 返回 422。
片段召回预算为 100，问答证据规模不变。
标签、区域和阶段筛选在片段召回前限定文档范围，召回后继续复核。

部署后使用相同用户、相同库范围，对同一已入库资料分别测试：完整标题、标题中的关键词、
独有标签、关键词与标签组合，以及预设口语问题。记录目标 UUID 是否返回，不以总条数代替召回质量。
MCP `top_k` 仍表示返回卡片上限，不表示底层片段召回预算。
模糊语义质量仍须通过题集实测，扩大候选不能保证所有口语问题都会命中。

统一检索及MCP问答使用平台保存的默认模型；产品模型配置存在时不复活旧环境默认模型。
长口语问题可由同一受信模型生成最多两个短检索词组，保留原问题，不执行生成文本中的指令。
生成最多等待4秒，无模型/超时/无效JSON回退原查询。每个扩展底座调用最多等待4秒，
扩展失败保留原召回；三个查询片段去重交错合并后最多100条，元信息共享一次2000行扫描预算。
所有扩展沿用同一KB、目录及业务筛选边界，最终仍执行权限复核，不保证语义转换一定正确。

问答响应增加`answer_status`和`answer_message`：`not_requested`、`answered`、
`insufficient_evidence`、`unavailable`。模型结果须引用已放行证据编号，否则明确降级；
无依据使用固定拒答，不输出模型编造内容或无关引用。上线后仍需人工核对答案与引用的一致性。

## 预览

脚本加载最多 15 秒，编辑器启动最多 30 秒，编辑器就绪后取件/转换最多 120 秒。
只有 `onDocumentReady` 才代表文档成功打开；`onAppReady` 只代表编辑器应用启动。
警告不等于加载失败，真正的错误和有限超时仍会停止加载并允许重试。

Document Server 的受控取件 URL 必须是绝对 HTTP(S) 地址。优先使用
`ONLYOFFICE_INTERNAL_BASE_URL`，缺省使用 `KAP_PUBLIC_BASE_URL`；无效配置返回安全错误码，
不输出密钥或存储路径。基址必须是有效 HTTP(S) origin，只允许空路径或根路径，
端口须有效，不能包含用户凭据、查询或片段。浏览器仍使用 `ONLYOFFICE_DOCUMENT_SERVER_URL`，其 origin 必须与前端 CSP 一致。

部署后用确实有原文权限的业务身份打开小型和较大 DOCX/XLSX/PPTX，测试首次加载、关闭重开和失败重试。
同时确认无权身份仍无法签发预览凭证，过期和撤销令牌仍不可取件。
公开 `/healthcheck` 或 `api.js` 返回 200 不能证明受控文件能由 Document Server 取回。
如果仍超时，需要对照该次请求的时间检查 Document Server 转换/取件日志与平台请求日志；
不要分享 `ft`、Cookie、JWT 或完整预览配置。没有真实文档就绪证据前，不关闭验收问题。

ONLYOFFICE 事件语义参见：https://api.onlyoffice.com/docs/docs-api/usage-api/config/events

## 多扩展词排序补充

元信息排序先按匹配质量分组（精确标题、标题前缀、标题包含、精确标签），同组再按原词和扩展词顺序排序。SQL CASE 条件也按此顺序排列，避免较早词的宽泛标签遮蔽较后词的标题，即使同一资料同时命中标签和标题也一样。可见候选上限、总扫描上限及权限检查不变。该规则不保证模型为每个口语问题生成正确概念，仍须用真实模型和原验收题验证。

## 问答总期限与阶段诊断

问答、生成、总结及检查共享一次端到端处理预算，包含查询规划、召回、卡片、原文处理、证据脱敏、答案生成和审计，不给每个阶段重新分配一份完整预算。预算不超过30秒且不超过MCP操作超时的80%，为事务回滚、失败审计和协议响应留出余量。普通只返回卡片的检索不改变原有期限。

达到期限会取消正在等待的处理、回滚事务，并记录安全失败审计；返回`answer_status=unavailable`、明确重试说明、空答案和空引用，而不是无依据拒答或成功。完整构建且已过权限过滤的卡片可保留，不返回尚未完成的原文或生成内容。事务清理或审计失败不会伪装成问答成功。

`knowledge_qa_stage`记录阶段及前一阶段耗时，`knowledge_qa_deadline`记录超时阶段及总耗时；通过同一trace关联，不记录问题、原文、模型输出或凭据。此收口不证明供应商速度改善；上线后仍须复测正常题、无依据题、冲突资料题和多角色权限，并检查具体慢点，不能以不再出现传输504代替业务问答验收。

## 证据处理并发与语义规划诊断

父文件全文及兜底片段按资产有界并行处理，同一阶段最多两份资料同时处理；数据库查询在启动工作任务前完成，不并发共享AsyncSession。仍保留原有父文件数量/字符上限、六份片段资料预算、每份最多两个成功片段及原文权限和脱敏失败关闭策略；同一资料内的失败片段仍按原顺序继续尝试。输出按输入召回顺序合并，不按完成先后重新编号引用。取消或异常时，取消并等待所有运行/排队工作任务结束后再返回。

`retrieval_query_planning`只记录规划状态（expanded、original_only、not_needed、unconfigured、timeout、model_error、invalid_response、blank）、查询数量、耗时和trace；召回日志增加实际使用查询数量。不记录原问题、扩展词、原文或上游异常文本。单独脚本的一次模型输出不代表实际请求采用了相同扩展；须关联同次请求的规划、召回及阶段日志。有限并发不保证任意供应商在总期限内完成，也不等于原口语检索题已通过。
