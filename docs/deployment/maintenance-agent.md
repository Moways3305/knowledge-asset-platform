# 知识维护 Agent

依据《智能体模块产品需求文档：知识维护 Agent V0.1》实现。“智能体中心”为侧边栏独立一级模块，与“知识库”并列；手机端也有独立入口。同一个预置 Agent 按公司库、项目库分别配置；默认不开启定期巡检，也不授予正文处理权限。

## 运行范围与默认值

- 检查所选公司、项目知识库全部有效资料的当前版本；个人库、已删除、归档、弃用资产和历史版本不参与。比较范围为同一知识库。
- 北京时间每日 02:00 增量巡检、周日全量巡检，09:00 按维护人汇总摘要。首次运行全量；距上次全量满七天也补做全量。时间均可配置。
- 每天重新检查复核到期、未处理纠错和待更新事项，即使正文未变化。长期未处理阈值默认七天，可调整。
- 信息完整性、可用性、维护状态、重复与版本关系、内容质量五类检查全部启用。必要标签与必要章节由知识库配置。
- 重复判断包括文件校验值相同、标题相似、标题去版本号后相同。相似标题默认阈值 0.85；后两者为待人工核对线索，不作自动替换。对照集合包括同库未变更的资产。
- 质量分析可跟随平台默认生成模型，也可按知识库指定平台已接入且启用的生成模型。在巡检设置中选择，模型接入和凭据由平台统一管理。检查摘要与正文不符、仅封面或目录、必要章节缺失或明显截断，输出标记为“疑似”，直接矛盾必须带能在本次正文中找到的引用；全篇缺章或仅封面判断保存全部分段检查后的汇总依据。指定模型停用、删除、能力不匹配或凭据无法读取时，标为未完成，不回退到其他模型，也不复用历史质量检查结果。

## 权限与处理

配置由公司治理角色或相应项目经理保存。持久化记录授权人及当时的业务身份，定期执行重新读取该身份、项目成员关系和原文授权；不依赖浏览器登录会话。纯管理员不获得业务正文访问权。正文与文件检查需要明确授权，并同时满足平台原文权限和智能体渠道权限，A4 等限制继续生效。

每项问题带首次/最近发现时间、版本、事实指纹、依据和处理历史。相同问题更新原记录；变更事实或版本重新发现。可标记处理中、提交复检、暂缓（原因和期限）、误报（原因）；语义问题还可由有原文权限的人员确认已解决。客观问题经重新检查确认修正后关闭。通知已读与问题状态独立。

当前有权限的维护人接收任务；维护人缺失、停用或失去管理权限时回退到有权限的知识库管理人。列表、任务中心、依据、通知投递均重新核对权限与责任。正文依据不随通知外发，资料变更后旧版本依据隐藏。Agent 不直接改变资产、密级、目录、审核结论或替代关系。

## 后台执行与覆盖说明

Celery beat 每分钟提交一个普通队列任务。数据库保存扫描游标、运行状态、三分钟租约与唯一持有令牌。每次领取一个资产的一批工作，并把问题、分段/对照游标、摘要事件原子提交。一条消息在45秒时间预算内最多领取250批工作，开始下一批前检查预算；外部模型调用最多等待四十秒，期间不持有数据库事务。进程中断后由下一次调度续跑；旧持有者的迟到结果不能回写。配置变化取消运行；资产、比较对象、权限变化后丢弃迟到结果并记录原因。

正文与摘要按窗口检查直至结束，同库比较按 UUID 分页继续，不再因正文总长、200 个分块或500份对照数量而跳过。正文每批最多6,000字、摘要每批最多2,500字，窗口重叠250字；旧 settings.max_body_chars 仅作为每批正文预算的兼容约束。对超长摘要逐段与正文窗口核对，全部覆盖后才完成。正文片段不能单独得出全文缺章或只有封面的结论。每资产保存已检查字符、分段数、同库对照进度及失败窗口的位置；不保存原始模型响应或正文到工作状态。

瞬时连接、超时、限流、服务端异常、响应不完整与引用核对失败每窗口最多尝试3次，重试间隔至少20秒，由后续调度执行。仍失败则记录可解释的未完成原因；用户可重试未完成项，配置与资料指纹未变化时复用已完成前缀，变化时重新检查。永久配置/授权错误不反复调用模型。完成检查可以发现问题，不代表资产没有问题。增量扫描对未变化且已完成的质量分析复用结果，定期全量重新分析。

通知通过现有事务 Outbox 投影到站内通知与企业微信；同一接收人每天一个摘要事件，投递沿用既有重试与可观测状态。外部渠道无法与数据库构成原子提交，供应商已接收但本地未确认的故障窗口仍可能导致重发。解析、索引、文件异常和巡检技术失败汇总通知运维，不携带原文、内部存储地址或模型凭据。

## 迁移与验证

模型选择保存在现有策略的 JSON settings 中，旧策略默认 `system_default`，此次配置体验更新不需要新增数据库迁移。首次使用点击“配置并开始”，保存模型和授权后可直接发起巡检；已有任务时入口改为“查看巡检进度”。修改配置会取消尚未完成的旧巡检。

迁移 `0089_maintenance_agent` 新建六张功能表，不改动已有资产。部署时正常执行迁移并更新 API、worker、beat、前端；按知识库人工保存授权配置后再运行。迁移前备份数据库，降级前停止本功能调度并结束正在运行的巡检，保留问题与处理历史的备份。

自动化验证包括五类规则、范围和权限、日程去重、租约恢复、迟到结果、原文撤权、模型异常、问题状态和通知，以及 PostgreSQL 独立事务竞争测试。前端验收脚本 `scripts/maintenance-agent.ui-qa.mjs` 检查 1440、1024、390 宽度下的正常、空、错误、禁止访问状态和设置/问题处理操作；已加入全站 UI 验收。


## 统一知识库与巡检明细（0090）

全平台取消素材区/资产区的业务区分。现有 `zone` 字段和枚举仅供旧客户端与历史审计兼容，读取不再按其过滤；新入库使用统一兼容值，不批量修改现有文件、正文或旧审核记录。个人知识仍仅本人可见，项目成员、密级和原文授权规则继续生效。

项目验证审核记录真实分享/客户验证证据和审核结论，不再改变分区，不作为资料在本库使用或申请公司发布的前置门槛。旧 `material_to_asset` 类型保留为内部兼容标识，界面显示“资料验证”；已存在的待审任务继续按证据和审批权限办理。公司发布仍须完成既有公司治理审批。个人资料无需再次确认“成为资产”，旧确认接口仅返回无需操作。

巡检仅覆盖所选公司/项目库的 `active`、`needs_update` 资料，排除个人库、删除、归档、停用及未完成入库的资料。迁移 `0090_maintenance_run_details` 为运行增加范围快照和逐项结果表，不回填旧记录。新任务提交时固定目标清单，每项结果、游标、计数在同一事务提交，租约恢复不会生成重复明细。任务期间失效或移库的目标记录为跳过；之后新增或恢复的资料在下一轮纳入。零目标直接结束为 `empty`，不再显示“检查完成”。

“查看巡检详情”展示提交时范围、当时授权与设置、五类检查覆盖、问题规则和未完成原因；每页25项，读取时重新校验当前管理权限，删除或移库的标题不再展示。不会在明细中返回正文、引用片段、内部存储路径或模型密钥。旧任务明确提示未保存逐项详情，实时范围核对与历史结果分开显示。部署需同时升级 API、worker、beat 和前端，并迁移至0090；已有运行按旧游标继续，不能伪造新明细。


## 记录管理、分批进度与无干扰更新（0091）

迁移 `0091_maintenance_batch_progress` 为逐项结果增加可空 JSON 工作进度；旧记录保留，不虚构此前未记录的分段数据。运行中的记录可取消；已结束记录可单条或批量删除（单次100条），删除运行与逐项明细，保留知识资料、问题、处理历史、通知及配置。删除动作另记操作审计。取消撤销租约令牌，迟到模型结果无法回写；取消后可另建重试记录。没有逐项历史的旧记录需发起新的全面巡检。

记录采用紧凑表格，详情在独立抽屉查看。当前范围轮询不清空列表、抽屉或重置设置草稿；只在首次加载或切换范围时显示加载状态。后台临时失败保留上次数据并提示；401/403/404清除受限详情。任务活动时每15秒更新，页面隐藏时暂停请求；慢请求不叠加，终态停止轮询。服务端策略版本变化不会重挂载编辑器覆盖未保存草稿，保存时仍校验 expected_revision 防止覆盖他人修改。
