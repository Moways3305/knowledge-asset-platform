# 知识维护 Agent

依据《智能体模块产品需求文档：知识维护 Agent V0.1》实现。入口为“知识库 → 智能体中心”。同一个预置 Agent 按公司库、项目库分别配置；默认不开启定期巡检，也不授予正文处理权限。

## 运行范围与默认值

- 只检查公司、项目知识库中资产区的当前有效版本；个人库、素材区、已删除、归档、弃用资产和历史版本不参与。比较范围为同一知识库。
- 北京时间每日 02:00 增量巡检、周日全量巡检，09:00 按维护人汇总摘要。首次运行全量；距上次全量满七天也补做全量。时间均可配置。
- 每天重新检查复核到期、未处理纠错和待更新事项，即使正文未变化。长期未处理阈值默认七天，可调整。
- 信息完整性、可用性、维护状态、重复与版本关系、内容质量五类检查全部启用。必要标签与必要章节由知识库配置。
- 重复判断包括文件校验值相同、标题相似、标题去版本号后相同。相似标题默认阈值 0.85；后两者为待人工核对线索，不作自动替换。对照集合包括同库未变更的资产。
- 质量分析复用平台默认生成模型。检查摘要与正文不符、仅封面或目录、必要章节缺失或明显截断，输出标记为“疑似”，必须带能在本次正文中找到的引用。

## 权限与处理

配置由公司治理角色或相应项目经理保存。持久化记录授权人及当时的业务身份，定期执行重新读取该身份、项目成员关系和原文授权；不依赖浏览器登录会话。纯管理员不获得业务正文访问权。正文与文件检查需要明确授权，并同时满足平台原文权限和智能体渠道权限，A4 等限制继续生效。

每项问题带首次/最近发现时间、版本、事实指纹、依据和处理历史。相同问题更新原记录；变更事实或版本重新发现。可标记处理中、提交复检、暂缓（原因和期限）、误报（原因）；语义问题还可由有原文权限的人员确认已解决。客观问题经重新检查确认修正后关闭。通知已读与问题状态独立。

当前有权限的维护人接收任务；维护人缺失、停用或失去管理权限时回退到有权限的知识库管理人。列表、任务中心、依据、通知投递均重新核对权限与责任。正文依据不随通知外发，资料变更后旧版本依据隐藏。Agent 不直接改变资产、密级、目录、审核结论或替代关系。

## 后台执行与覆盖说明

Celery beat 每分钟提交一个普通队列任务。数据库保存扫描游标、运行状态、三分钟租约与唯一持有令牌。每次处理一个资产，并把问题、游标、摘要事件原子提交。每条消息最多处理八个资产；外部模型调用最多等待四十秒，期间不持有数据库事务。进程中断后由下一次调度续跑；旧持有者的迟到结果不能回写。配置变化取消运行；资产、比较对象、权限变化后丢弃迟到结果并记录原因。

正文默认每份 24,000 字，可配置为 1,000—60,000 字；最多 200 个有效分块，摘要最多约 5,000 字，同库对照最多 500 份资产。超过上限、未授权、解析或索引尚未完成、模型不可用、引用无法核对均记录覆盖不足，绝不标为检查通过。界面分别展示目标、完成、未完成和跳过数量。完成检查可以发现问题，不代表资产没有问题。增量扫描对未变化且已完成的质量分析复用结果，定期全量重新分析。

通知通过现有事务 Outbox 投影到站内通知与企业微信；同一接收人每天一个摘要事件，投递沿用既有重试与可观测状态。外部渠道无法与数据库构成原子提交，供应商已接收但本地未确认的故障窗口仍可能导致重发。解析、索引、文件异常和巡检技术失败汇总通知运维，不携带原文、内部存储地址或模型凭据。

## 迁移与验证

迁移 `0089_maintenance_agent` 新建六张功能表，不改动已有资产。部署时正常执行迁移并更新 API、worker、beat、前端；按知识库人工保存授权配置后再运行。迁移前备份数据库，降级前停止本功能调度并结束正在运行的巡检，保留问题与处理历史的备份。

自动化验证包括五类规则、范围和权限、日程去重、租约恢复、迟到结果、原文撤权、模型异常、问题状态和通知，以及 PostgreSQL 独立事务竞争测试。前端验收脚本 `scripts/maintenance-agent.ui-qa.mjs` 检查 1440、1024、390 宽度下的正常、空、错误、禁止访问状态和设置/问题处理操作；已加入全站 UI 验收。
