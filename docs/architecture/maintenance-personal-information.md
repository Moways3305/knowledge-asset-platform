# 知识维护 Agent：敏感个人信息检查

## 检查与处理

新增 `privacy` 分类及 `personal_information` 疑似问题，进入现有待办、处理、暂缓、误报、复检和关闭流程。类型包括电话、邮箱、身份证、银行卡和长账号，以及明确标注的姓名、住址、个人证件、健康、生物识别、个人财务字段。全角、常见分隔符与零宽字符在本地归一化后识别，位置仍指向原始解析文本。

复用规则脱敏引擎已有的识别模式，抽出无网络依赖的公共模块；不新增模型服务或第三方数据传输。仅授权的公司/项目库参与，原文和 Agent 渠道权限继续在每批处理、落库和读取时检查。无正文授权或缺少可用解析文本时，隐私覆盖状态明确为未完成。

隐私游标独立于质量分析游标：正文每批 6,000 字符并向前多读取 512 字符以核对跨边界实体，只有起点属于本批的实体计数；摘要扫描当前版本全部展示变体。模型不可用或质量分析失败不会提前结束本地隐私检查。重试复用原有围栏、租约、事务与当前版本校验。规则版本进入扫描指纹，避免复用旧版“未检查隐私”的增量结果。

隐私问题证据和工作状态只保存受控类型、数量、来源、数值位置及是否省略后续位置；最多展示 20 处位置，完整计数保留。不存储命中原值或正文摘录。摘要位置另标注短摘要、完整摘要、脱敏摘要等来源。修正后复检未再命中且隐私检查完整时，自动关闭此问题；部分失败不能当作已修正。

## 输出防线

- 质量分析发送前遮盖可识别的个人信息，保持字符位置，返回证据仍须通过引用核对。
- 新问题证据、用户处理原因写入前过滤；历史证据和处理记录读取时再次过滤。
- 知识摘要列表、详情、检索卡片、版本比较、治理列表在输出边界过滤，不只依赖历史摘要曾被标记为“脱敏”。
- 站内消息投影与企业微信实际发送共用识别器；收件人路由标识不作为消息正文发出。
- JSON 日志过滤消息、嵌套字段及禁止记录的正文/凭证载体；审计写入及历史快照投影同步过滤个人字段，保留必要的 UUID 与安全状态码。
- 脱敏异常时显示固定不可展示提示，不把原值作为异常兜底返回。运行错误只保存固定错误码。

## 覆盖边界

这是保守的本地模式和字段上下文识别，不是任意语言、任意姓名或任意上下文的通用实体识别器。无文字解析的扫描件、图片内部信息、模糊表达、无明确上下文的姓名仍可能漏检；“未检出”不等于证明资料完全不含个人信息。敏感原文仍受原有访问控制保护，人工核实与资料分级不能由一次扫描替代。检测不会擅自覆写原文件。

已存在于数据库、备份或历史外部日志中的内容不会被这次代码更新物理擦除；读取和发送出口立即过滤可识别值。若需历史物理清理，应另做有范围、有备份的治理任务。

## 验证与参考

回归使用虚构标识，覆盖尾部实体、跨段边界、模型停用、授权不足、摘要变体、证据/游标不含原值、处理后复检关闭、历史展示过滤、企业微信发送和日志嵌套字段。无数据库结构变更，部署需更新 API、全部相关 worker 和前端；自动巡检是否开启沿用既有配置。
