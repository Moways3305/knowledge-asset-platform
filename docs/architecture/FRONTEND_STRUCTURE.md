# 前端结构与接口边界

前端以已确认的桌面端和手机端新设计为基线，页面结构、CSS 与导航遵循 [设计基线](../frontend_design_baseline.md)。旧页面布局不作为设计依据；数据、权限和业务流转以后端接口为准。

## 分层

- `src/pages/*Page.tsx`：路由视图，组合工作区、筛选、列表、详情、弹窗和操作区域。
- `src/pages/controllers/<Feature>/use<Feature>.tsx`：该页面的数据加载、请求竞争保护、表单状态和用户动作。当前已拆分 KnowledgeList、KnowledgeDetail、MyKnowledge、ProjectSettings、Review、AdminIngest、AdminPeople、AdminWeKnoraModels。
- 同目录 `model.tsx`：原页面的类型、选项、展示映射和纯辅助逻辑。少量状态标签渲染仍使用 JSX。
- 入库管理进一步拆分恢复摘要、待恢复队列、作业记录、运行诊断视图；状态保留在共同 controller，避免切换视图丢失操作状态。
- `src/api/`：领域请求与 DTO 映射。页面不直接调用 fetch、HTTP 动词封装或自行处理 CSRF。
- `src/api/http.ts`：认证 cookie、CSRF 刷新一次、错误归一化、JSON 与 multipart 传输。multipart 不手工设置 Content-Type，保留文件字节、元数据与取消信号。
- `src/api/generated/routes.ts`：从后端 OpenAPI 生成 HTTP 方法/路径类型。业务 DTO 仍在领域模块和 `src/types/`，不能用路径类型替代响应验证。

这是对高复杂度页面的分层，不要求简单页面为了目录结构拆分空壳，也没有将全部历史代码重写。

## 接口对照维护

1. 后端变更先运行 `npm run api:export` 更新 OpenAPI。
2. 在领域 API 中接入请求，并由页面或控制器调用。
3. 对于确实没有前端入口的接口，在 `docs/api/frontend-api-review.json` 逐项记录用途、缺口和建议入口。禁止以笼统通配规则隐藏新增接口。
4. 运行 `npm run api:frontend:generate` 更新路径类型及 `docs/api/FRONTEND_API_COVERAGE.md`。
5. CI 的 `npm run api:frontend:check` 检查请求路径、动态资源绑定、未记录接口和生成文件漂移；后端 CI 独立检查 OpenAPI 是否与实现一致。

静态扫描识别请求方法、字面量/模板路径及直接导入/转导出，不能证明按钮可点击、调用链必达或真实服务业务成功。覆盖表明确区分未接入、部分覆盖、替代流程、动态资源和系统集成。路径参数为字符串模板，并不能校验 UUID 或禁止其含斜杠；适配器应编码用户提供的路径值。

## 行为边界与验证

- 审核通知及项目待办的定向链接使用单条审核详情接口，避免在列表第一页查找。记录是否可见/可决定由后端判定；请求被拒绝时不回退扫描其他列表。
- 页面筛选、项目身份、选中项、抽屉关闭和来源返回按现有设计执行。提取状态逻辑时保留请求序号及 effect cleanup。
- 页面测试继续从用户操作出发，验证加载、失败、空态、权限、审批反馈和导航；架构测试检查页面不绕过领域 API 发请求。
- 上传传输测试覆盖 CSRF 重试和不重试权限拒绝，确认重试仍使用同一 FormData 和 AbortSignal。
- 本地浏览器复查桌面和手机端布局。静态对照、组件模拟和本地服务检查不替代生产环境业务验收。

## 补齐业务入口（2026-11-03）

新增操作集中在所属页面的标题操作区、单条记录操作区或已有维护面板，复用详情抽屉；手机端使用整屏抽屉。领域请求仍位于 `src/api/`，交互组件位于 `src/components/operations/`。

| 所属页面 | 补齐入口 |
| --- | --- |
| 登录安全 | 查询账号会话、撤销会话、企业微信身份核对（先预览后应用） |
| 人员权限的外部助手区域 | 注册助手，绑定业务身份和知识范围；一次性凭证默认遮挡，关闭后清除 |
| 告警设置 | 告警通知历史 |
| 审计日志 | 同一追踪标识的关联事件；有权限的问答调用详情与权限判定明细 |
| 项目问答 | 本次问答的调用详情与引用权限判定 |
| 入库管理的运行诊断 | 系统运行概况、知识运行概况、历史正文回填；回填作业进入已有作业记录 |
| 知识维护 | 知识运行概况，包括基础计数和后端返回的建议 |
| 资料详情 | 已归档资料的恢复申请、恢复确认，遵守后端生命周期权限和替代版本冲突 |
| 我上传的资料 | 已产生资料的解析状态同步，不触发重新解析 |

本轮原清单的 17 项中，14 项补充直接入口，3 项保留已有替代流程：批量提交项目、批量升级公司两个旧接口固定返回 `publication_naming_required`，继续使用逐条目录及命名确认；批量资产化继续走既有预检、证据补充和提交流程，不增加绕过预检的按钮。

所有写操作显示后端结果并防止重复提交；会话撤销保留当前会话。纯管理员使用后端允许的候选账号接口，不调用仅治理身份可用的人员清单。恢复申请不表示恢复已完成，身份预览不表示已应用，解析状态同步不表示解析成功。角色可见性只是前端提示，最终权限和业务条件由接口决定。
