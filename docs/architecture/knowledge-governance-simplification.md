# 知识治理简化

复核用于确认资料仍然适用，不是所有文件的必填字段。空日期表示不定期复核；指定日期到期时提醒；周期复核在确认通过后计算下次日期。已有日期原样保留。未复核、普通元数据变化、未单独指定维护人不自动产生强制待办。

Agent 中的摘要、必要标签、分类和维护人缺失归入“完善建议”，可单独查看，不进入待办摘要通知。没有配置必要标签时不检查空标签。`missing_review_date` 退出当前问题查询与通知，后台逐批标记为不适用，保留历史审计。技术故障、逾期、用户反馈、基于证据的内容问题仍需处理。知识维护列表引用同一批 Agent 问题，不另建一套问题记录；跨项目/密级的不可见关联问题不计入数量。

`maintenance_reconcile` 在资料写入事务内同步已经满足的客观条件，不调用模型、不自动判定正文质量。正文质量和重复线索仍需人工判断或复检。反馈可修正后验证，也可不采纳、标记重复、撤回、重新打开；知识库管理人可以核实并关闭已修正的反馈。关闭保留处理记录，不等同于删除历史消息。

维护责任由 `knowledge_responsibility` 统一计算：有效的指定维护人优先，否则回退到当前知识库管理人。单纯指定姓名不扩大权限。新授权必须由公司库管理人明确开启，仅适用一份 L1—L4 公司资料，允许人工原文访问、元数据维护与反馈处理，不授予 Agent 正文权限、密级调整、新版发布或生命周期管理权。撤销/更换授权或调整密级会撤销旧预览凭证。项目和个人库继续使用原有权限规则。

公司治理与详情的新版替代都调用 `knowledge_review.replace`，按稳定顺序锁定两份资料，校验双方版本、来源、范围、密级及未处理反馈，在同一事务内确认新版内容、建立关系、归档旧版。公司治理中的新版替代只允许逐份确认，普通归档仍可批量处理。

迁移 `0093_optional_knowledge_review` 仅增加周期天数和显式维护授权字段；已有责任人与日期不变，授权默认关闭。部署须迁移到该提交的 Alembic head，保留正常停写备份流程。

## 重复实现与死代码清理

- 22 处相同的 HTTP 拒绝响应构造函数改用已有 `core.errors.denied`，保留导入名称兼容调用方。
- 三处重复时间戳归一逻辑复用 `db.utils.as_utc`。
- Agent 与人工维护不再分别实现维护人资格/责任分派。
- 详情与公司治理共用新版选择组件，删除原有重复查找状态、手工 ID 输入和额外核对按钮流程。
- 移除强制日期分支、先复核再采用新版的重复门槛，以及相应未使用导入。

全仓检查使用 Python AST 的函数体/签名比对、引用搜索、Ruff、TypeScript 和 ESLint；相似但权限语义不同的函数未机械合并。API、Celery 入口和历史迁移/部署脚本不以普通调用数判断为死代码。回归覆盖并发版本校验、授权撤销、迁移保留旧值、反馈各出口、问题同步及表单草稿保留。
