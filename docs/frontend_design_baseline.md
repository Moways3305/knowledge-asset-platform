# KAP 前端设计基线

## 适用范围

本文件是 Kivo（博维知识资产平台）唯一的前端设计与迁移基线。生产路由继续由
`src/App.tsx` 管理，唯一应用外壳是 `src/layouts/AppLayout.tsx`。页面迁移只能在现有
路由和组件树内完成，不得新增 `src/legacy`、`src/new-*`、`src/v2` 或静态演示页面。

## 视觉令牌

令牌统一定义在 `src/layouts/AppLayout.css` 的首个 `:root` 中：

| 类别 | 规则 |
| --- | --- |
| 品牌 | 主色 `#1F2D75`；辅助色 `#4A6FA5`、`#A8B8CC`、`#C9A962` |
| 背景 | 页面画布使用冷浅灰；顶栏、表格和表单使用白色；不使用装饰渐变替代内容层级 |
| 文字 | 标题、正文、次要说明和弱提示分四级；长标识允许换行或省略，不得撑宽页面 |
| 状态 | success、warning、danger、info 均包含前景、浅背景与边框，不只依靠颜色表达 |
| 间距 | 以 4、8、16、24、32、48px 为基础；页面与组件不得重复定义同义魔法数 |
| 圆角 | 控件 5px、容器 8px；整页内容不放入悬浮大卡片 |
| 尺寸 | 按钮/表单 38px，小按钮 32px，表头 40px，表格行 48px |
| 层级 | base、sticky、header、popover、modal 使用统一 z-index token |

## 应用外壳

- 左侧为深靛蓝产品导航，默认展示图标和中文名称；折叠后保留图标、可访问名称和 tooltip。
- 导航入口继续使用 `auth/permissions.ts` 的能力谓词；项目链接必须来自 `/auth/me` 的真实项目 ID。
- 顶部只放真实公司品牌、工作台上下文和 `IdentityMenu`，不得添加假通知、假头像或假成员数。
- 左侧导航和主内容分别滚动。桌面端 shell 占满可用视口，但内容高度不被截断。
- 页面主体宽度不超过 1320px；表格在自身容器内横向滚动，`body` 不得横向溢出。

## 通用组件

- 页面结构：`ProductPage` → `PageHeader` → `PageToolbar`/`FilterBar` → `PageSection`。
- 按钮：使用 `Button` 或兼容的统一按钮 class；主、次、危险操作必须保持语义一致。
- 表格：使用 `DataTable`。加载和空状态占整行，表头与行高使用 token，宽表只在表格容器滚动。
- 表单：使用 `FormField`。标签在控件上方，提示与错误分别使用弱提示和错误色。
- 状态：使用 `StatusBadge` 的语义 tone；未知上游值必须能换行，不能撑破列。
- 空/加载/错误：使用 `EmptyState` 或 `LoadingError`，保留重试、权限不足和禁用原因。
- 操作型页面保持“标题 + 工具栏 + 筛选 + 表格/列表 + 抽屉或弹窗”，不改成卡片瀑布流。

## 页面迁移顺序

1. 今日工作台
2. 知识资产库与知识详情
3. 上传与资产化确认
4. 项目知识与项目设置
5. 原文预览
6. 审核
7. 管理后台各页
8. 帮助页

## 每页完成清单

每张页面迁移任务必须同时证明：

- 真实加载、空状态和错误状态均可用。
- 所有可见按钮均连接真实操作，包含禁用、确认和失败反馈。
- 数据来自现有真实 API，不增加 mock、演示统计或静态身份。
- 导航、页面守卫和后端权限口径保持一致。
- 在 1440px 与 1920px 完成桌面截图，检查裁切、重叠、横向 body 溢出和长文本。
- 删除被替代的页面结构、样式和组件调用，并用 diff 或静态测试证明没有双轨实现。
- 运行目标测试、全量前端测试、Lint 和生产构建。

## 安全边界

页面和测试不得将 token、API key、原文、存储路径、WeKnora 内部 ID 或上游错误正文写入
DOM、截图和文档。身份、权限和敏感配置不得写入 `localStorage` 或 `sessionStorage`；前端入口
过滤只改善体验，后端权限校验始终是权威。
