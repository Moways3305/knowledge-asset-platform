### 另外两项验收反馈

- 正文唯一编号检索：在现有 chunk 上加入 PostgreSQL `simple` GIN 表达式索引，完整编号再次精确校验；只返回当前有效版本，并按实时原文权限过滤正文命中。跨块候选须在有原文权限后，以该版本受控 Markdown 的完整字节及 SHA256 核对，不能凭块长猜测原文连续；缺失、损坏或超出读取预算时不接纳跨块候选。查询不生成或回填文件。仅摘要可见的账号不能借私有正文标记发现新资料。普通自然语言仍走既有召回。0081 自动覆盖已有 chunks，无需重传；普通事务内建索引期间允许读取，但会阻塞 chunk 写入，应低峰部署。
- 问答缺项说明：保留 `insufficient_evidence`，允许验证过的必要参数名及可定位原句引用。明确金额计算且给出比例时，可说明缺少计算基数；不自行选择收入/利润作为基数，不生成缺乏依据的金额。无可用依据仍使用安全拒答。

### 验证与限制

新增失败路径均用虚构数据或本地替身，不修改生产审批、授权、目录或业务资料。SQLite 用于多数服务/API 回归；GIN、迁移及真正行锁等待必须通过 CI 的 PostgreSQL 专项，跳过不能算通过。完整前后端测试、类型、格式、架构及 OpenAPI 检查随 PR 执行。部署后仍需针对正文编号、缺参数问答、拒绝终态三个反馈做线上复验。

## 工作台运行信号下钻

- `index_failed`、`parse_failed`：进入 `/admin/ingest`，由索引维护页展示安全计数并提供显式操作。
- `kb_init_failed`：按公司、个人和具体项目拆成独立安全卡片。公司治理角色进入 `/admin/company-kb`；个人失败进入 `/my/knowledge`；对应项目经理进入受后端项目范围过滤的 `/admin/weknora-models`，普通项目成员只进入项目状态页。跨 scope 失败不再误导到公司 KB。
- 原文申请类信号：进入 `/original-access`。
- 生命周期治理信号：进入现有知识治理页面。

所有下钻仅使用已注册的 KAP 页面路由；浏览器不持有 WeKnora KB ID、模型内部 ID、存储引用、密钥或上游错误正文，后端权限仍是最终裁决。
